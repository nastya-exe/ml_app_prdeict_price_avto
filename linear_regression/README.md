# Выводы о проделанной работе

## 1. Что было сделано
*   **EDA:** Очищены текстовые признаки (`engine`, `max_power`, `mileage`) от единиц измерения. 
* Обработка крутящего момент (`torque`) и оборотов (`max_torque_rpm`) с помощью регулярных выражений и конвертации физических величин.
*   **Добавление признаков:** добавила признак удельной мощности `power_per_liter`. Выполнено логарифмирование сильно скошенных распределений признаков и целевой переменной (`selling_price`).
*   **Предобработка и кодирование:** Удалены аномальные выбросы. Проведено кодирование брендов через `TargetEncoder`, выполнено разбиение количества мест по категориальным бакетам (`pd.cut`) 
* и применен One-Hot Encoding для категориальных признаков. Данные масштабированы с помощью `StandardScaler`.
*   **Валидация и обучение:** Настроена кросс-валидация. С помощью `GridSearchCV` осуществлен подбор оптимальных гиперпараметров для моделей `Ridge`, `Lasso`.
*   **Веб приложение:** Создан веб-сервис на Streamlit.

## 3. Что дало наибольший прирост качества
1.  **Логарифмирование целевой переменной:** Переход к `log1p(selling_price)` убрал сильное смещение цен в сторону премиум-сегмента и сделал распределение более нормальным.
2.  **Обработка (`torque`):** Выделение чистых физических чисел из текстовых строк вместо их удаления сохранило важную информацию о тяге двигателя.
3.  **Target Encoding для брендов:** Кодирование марок средней ценой автомобиля позволило использовать текстовое поле высокой мощности без взрывного роста числа колонок при OHE.
4.  **Удаление выбросов:** Удаление выбросов убрало шумы

## 4. Что сделать не удалось и почему
*   **Добавление модели машины из name:** Было бы полезно из name достать информацию не только про марку машины, но и про модель, но это бы усложнило задание.
*   **Заполнение признаков медианой:** Я заполнила None значения медианой, хотя можно было глубже проанализировать данные и подобрать значения оптимальней.
*   **Обработка пропущенных значений в категориальных признаках:** Пропуски в текстовых полях заполнялись модой, другой подход мог бы уменьшить смещение в данных

## 5. Оценка разработанного сервиса

Приложение разбито на две страницы с EDA и предсказанием цены. Интерфейс получился чистым и не перегруженным. Решение 
разделить калькулятор и аналитику на две отдельные страницы через верхнее меню навигации себя полностью оправдало: 
пользователь может сразу считать цену, не отвлекаясь на сложные графики. Форма ввода данных по центру экрана, разбитая на три аккуратные колонки, 
выглядит намного удобнее, чем стандартная узкая колонка сбоку.

*   **Хорошо:** Хорошо получилась хитмапа - за счет выноса вниз страницы на всю ширину экрана она легко читается, а подписи не накладываются друг на друга.
* Удобны интерактивные графики.
* Также очень наглядным вышел график весов модели Plotly: разделение факторов на зеленые и красные позволяет сразу понять логику графика.
*   **Менее удачно:** Поля ввода для предсказания цены. Хотелось сделать их более удобными
